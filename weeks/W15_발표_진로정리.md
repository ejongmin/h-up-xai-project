## 발표 구성 (10분)
| 시간 | 내용 |
|---|---|
| 1분 | 왜 정확도가 아니라 수용성인가 |
| 2분 | 사건 정의와 시점 정합 — 발견한 함정 세 가지 |
| 2분 | 모델 성능, 기준선 대비 얼마인가 |
| 3분 | **모델이 놓친 것과 재무제표에 담기지 않는 정보** |
| 2분 | 진로 판단: 모델 개발 직무인가 리스크 심사 직무인가 |

성능 그래프에 시간을 쓰지 않는다. 3분 구간이 이 프로젝트가 가진 유일한 고유 결과다.

## 진로 판단에 쓸 근거 (15주간 축적한 것)
- 데이터 수집·정제에 실제로 쓴 시간 비율
- 모델링에 쓴 시간 대비 설명·소통에 쓴 시간
- 오분류 사례를 읽으며 필요하다고 느낀 역량
- 재미있었던 작업 / 견디기 힘들었던 작업 (주차별 블로그에서 역추적)

> 로드맵은 "무엇이 되고 싶다"가 아니라 **"다음 6개월에 무엇을 하겠다"**로 쓴다.

## 수기집 원고 방향
성공담이 아니라 **판단이 바뀐 지점**을 쓴다.
- 처음 세운 정의가 왜 틀렸고 어떻게 바뀌었는지
- 성능이 기대에 못 미쳤을 때 무엇을 했는지
- 실무자 검증을 접었을 때 무엇을 잃었다고 판단했는지
