# 재평가 사전 고정 (2026-10-10)

데이터 오류 수정과 분석 대상 변경 후 결과를 다시 계산하기 **전에** 기준을 적어 커밋한다.
아래 기준은 재계산 결과를 보고 바꾸지 않는다. 바꾸면 별도 실험으로 따로 보고한다.

배경: 외부 검토 결정 — 주 분석을 '관측 기간 내 첫 부실'로, 공시 단위 오류는 원자료 대조 후 원인 단계에서 수정,
학습 라벨의 관측 기간과 검증 시작의 겹침도 재평가 전에 처리.

## 1. 분석 대상

| 구분 | 정의 | 위상 |

| **관측 기간 내 첫 부실** | 기준시점 T 까지 **관측된** 부실 사건이 없는 기업-연도 | **주 분석** |
| 반복 부실 | T 이전에 관측된 사건이 있는 기업-연도 | 보조 분석 |
| 전체 | 둘을 합친 것 (기존 결과와 비교용) | 보조 분석 |

- "관측된 사건" = `events.csv` 의 사건(감사의견 비적정·회생절차 개시, 2015-01 이후 공시). 그 기업의 **첫 사건일 ≤ T** 이면 반복 부실.
- 2015년 이전 이력은 보이지 않는다. 그래서 이름을 '첫 부실'이 아니라 **'관측 기간 내 첫 부실'**로 쓴다.
  과거 이력 누락이 성능을 어느 방향으로 바꾸는지는 확정할 수 없다고 적는다.
- **집계 단위는 기업-연도 관측치로 통일한다.** 기업 수를 말할 때는 "고유 기업 N곳"으로 따로 표기한다.

## 2. 데이터 오류 처리 기준

원칙: 일괄 삭제·추정 배수 나눗셈을 하지 않는다. **같은 회사의 다른 공시로 확인된 경우에만** 고친다.

1. **단위 전환 확인** — 같은 회계연도 자산총계는 그 해 사업보고서(당기)와 다음 해 사업보고서(전기)에 두 번 공시된다.
   두 값의 비가 10³ 또는 10⁶ 의 ±1% 안이면 두 보고서 사이에 **단위가 바뀐 것**으로 확인한다.
2. 단위가 같은 연속 보고서를 한 구간으로 묶고, **가장 많은 연도를 차지하는 구간을 기준 단위**로 한다(동률이면 자산 1천억~600조 원 범위에 드는 구간).
   다른 구간의 **금액**(자산·매출 등)을 정확히 10ᵏ 로 환산한다.
3. **비율 변수는 바꾸지 않는다.** 분자·분모가 같은 보고서에서 오므로 단위가 상쇄된다(확인: 오류 보고서 안에서 BS·IS 가 같은 배율).
   영향을 받는 것은 **로그자산, 자산증가율, 매출증가율**뿐이며 수정 후 다시 산출한다.
4. **확인할 수 없는 불일치**(같은 연도 두 공시가 10배 넘게 다르지만 10³·10⁶ 이 아님, 또는 비교할 다음 해 보고서가 없음) →
   그 기업-연도의 **로그자산·증가율을 결측** 처리하고 비율은 유지한다.
5. **자산총계 ≤ 0** (빈 재무제표 응답) → 그 기업-연도의 **재무 변수 전체를 결측**으로 한다.
   0 으로 채워진 응답에서 "영업손실 아님" 같은 이진 변수가 거짓으로 만들어지기 때문이다.
6. 증가율의 분모가 0 이면 결측(무한대 금지).
7. 수정 내역은 `results/data_fix/단위수정_내역.csv` 에 행 단위로 남긴다.

> **구현 시 보완 (재계산 전, 2026-10-10)** — 결과를 보기 전에 고친 두 가지.
> - 2번의 기준 단위: "가장 많은 연도" 규칙은 **7년 연속 천원 단위였던 회사**에서 틀린 쪽을 기준으로 고른다.
>   그래서 **자산 중앙값이 10억~600조 원 범위에 드는 단위 구간 중** 연도가 가장 많은 것을 기준으로 한다(범위 안 구간이 없으면 연도 최다).
> - 4번의 확인 불가: 불일치는 두 보고서 사이에서 생기고 어느 쪽이 틀렸는지 정할 수 없으므로 **두 기업-연도 모두** 로그자산·증가율을 결측으로 한다.
> - 1번의 허용 폭: ±1% 로는 **재작성과 단위 전환이 겹친 경우**(전환 해에 전기 금액도 11%·21% 재작성)를 놓쳤다 — 7년 연속 천원 단위인 회사가 그대로 남았다.
>   같은 해 값의 두 공시 비가 10³·10⁶ 의 **0.67~1.5배** 안이면 전환으로 확인한다. 재작성으로 1000배가 생길 수는 없기 때문이다.
>   수정은 여전히 정확히 10ᵏ 로만 한다(재작성 값으로 바꾸지 않는다). 첫 빌드의 수정 내역만 보고 고쳤고, 모델 결과는 보지 않았다.
> - 판정 방식: 보고서마다 단위가 하나라는 가정이 깨졌다 — **당기 값만 1000배이고 같은 보고서의 전기 값은 정상**인 보고서가 있었고,
>   보고서 단위 연쇄 방식은 정상인 다음 해들을 1000배로 키웠다(첫 빌드의 수정 내역에서 발견, 모델 결과는 보지 않음).
>   그래서 **자기 시계열의 10³·10⁶ 점프를, 다른 해 보고서가 같은 배율로 확인할 때만** 단위 오류로 본다(`features.fix_units` docstring).
>   점프가 있는데 확인이 없으면 고치지 않고 두 해의 로그자산·증가율을 결측으로 둔다.
> - 배율 결정: 점프를 반올림해 배율을 정하면 **100만 배 오류에 실제 3.6배 성장이 겹친 해**를 10⁵ 로 읽어 놓친다.
>   다른 해 공시가 확인한 배율로 나눈 뒤 남는 변화가 0.2~5배면 단위 오류로 본다. 수백 배(10^2.5) 넘게 뛰었는데 확인이 없으면 두 해 결측.
> - 이 방법은 **전환이 일어난 경우만** 잡는다. 두 번째 빌드에서 **처음부터 끝까지 천원 단위로 보이는 회사들(자산 10억 원 미만 74행)**이 남았다.
>   확인할 공시가 없으므로 **로그자산만 결측**으로 둔다(증가율·비율은 같은 단위 안의 계산이라 유지). 수정 내역에 행 단위로 남는다.
> - (참고) 이 방법은 **전환이 일어난 경우만** 잡는다. 처음부터 끝까지 다른 단위로 공시한 회사는 잡지 못한다 — 수정 후 자산 10억 원 미만 행을 따로 집계해 보고한다.

## 3. 라벨 관측 기간과 검증 시작의 겹침 (엠바고)

- 문제: 학습 행의 라벨은 T 이후 400일의 사건으로 정해진다. 2021년 공시 학습 행의 라벨 창은 2022년(검증 구간)까지 이어져,
  **검증 시점에는 알 수 없던 사건**으로 학습했다(2,101행, 라벨 사건 25건이 검증 시작 이후 발생).
- **규칙**: 검증 단계의 학습 표본은 `T + 400일 < 검증 구간 첫날(1월 1일)` 인 행만 쓴다.
  롤링 오리진의 각 폴드에도 같은 규칙을 적용한다.
- **최종 모델(평가 구간용)은 학습 구간 전체**로 학습한다 — 학습 구간 라벨 창은 평가 시작(2024년) 전에 모두 끝난다(검사로 확인).
- 정제 기준(윈저라이즈 경계·대치값)은 검증 단계 학습 표본에서 계산한다.

## 4. 모델 설정 (바꾸지 않는다)

- 특성: 재무 27개 + 결측 더미. 과거 사건 여부는 **특성으로 넣지 않는다**(분석 대상을 가르는 데만 쓴다).
- 모델: 기존 앙상블(HistGB, `class_weight="balanced"`), 순위는 비보정 · 표시 확률은 isotonic 보정본.
- 학습 표본: 두 집단(첫 부실·반복) **모두**로 학습한다. 첫 부실 집단만으로 다시 학습하는 것은 **별도 실험**이다.
- 하이퍼파라미터·변수 집합·임계값 정의 변경 없음.

## 5. 재평가

- 평가 구간(2024~2025)을 **1회** 다시 연다. 이름은 "데이터 오류 수정 후 재평가". 완전히 새로운 독립 검증이 아니다.
- 보고: 주 분석(관측 기간 내 첫 부실) → 보조(반복, 전체) 순. 기존 결과와 수정 결과를 **나란히** 싣고 변경 이유를 적는다.
- 지표: PR-AUC(기준선 병기, 부트스트랩 1,000회 95% CI), 재현율@정밀도0.3, 상위 1·2·5·10% 표.
- **평가 결과를 보고 추가 튜닝하지 않는다.**

## 7. 실행 중 발견한 설정 일탈 (2026-10-11 — 검증 결과를 **본 뒤** 발견)

- **무엇**: 앙상블(HistGB)의 `early_stopping` 기본값 `'auto'` 는 **학습 표본이 1만 건을 넘을 때만** 켜진다.
  엠바고로 검증 단계 학습 표본이 11,376 → 9,273 이 되자 조기 종료가 꺼지고 반복이 64 → 400 으로 바뀌었다.
  §4 "모델 설정 변경 없음"을 데이터 크기가 몰래 어긴 것이다.
- **어떻게 발견했나**: 첫 재실행에서 검증 단계 모델의 평균 예측확률(실제의 1.8배)과 최종 모델의 Brier(크게 부풀림)가
  같은 설정이라기엔 너무 달랐다. 결과를 보고 찾은 것이므로 그렇게 적는다.
- **조치**: `early_stopping=True` 로 명시 고정 — **기존 주 모델의 실제 설정**이다(학습 11,376건 → 켜짐).
  성능이 좋아지는 쪽을 고른 것이 아니라 원래 설정으로 되돌린 것이다. 검증 단계 전부 다시 실행한다.
- **평가 구간 영향**: 최종 모델(학습 11,376건)은 원래 켜져 있었다 — 고정 전후 평가 구간 예측이 **완전히 같음**을 확인했다.
  따라서 평가 구간 재평가(순위 지표)는 다시 열지 않는다. 다만 **isotonic 보정본**은 내부 교차검증 표본(약 9,100건)에서
  조기 종료가 꺼진 채 산출됐으므로, 평가 구간의 보정본 수치는 "고정 전 설정"으로 표기하고 다시 열지 않는다.
- 이전(수정 전) 결과에서도 롤링 오리진 초기 폴드·보정 내부 적합은 1만 건 미만이라 꺼져 있었다 — 같은 원인의 비일관성이 원래 있었다.

## 8. 2차 재평가 사전 고정 (2026-10-13 — 코드 수정·재실행 **전**)

배경: 에이전트 코드 감사(2026-10-13)에서 라벨 누수가 확인됐다. 감사의견 사건일을 **최신 정정본의 접수일**로 잡아,
FY t 보고서에 이미 적힌 비적정 의견이 T 이후 사건으로 밀려 같은 행의 라벨이 됐다(131행, 그중 63행은 그 사건만으로 y=1).
함정 A-1(동어반복)이 일부 뚫려 있었던 것이다. 같은 이유로 T 에 이미 공개된 비적정이 '과거 사건'으로 잡히지 않았다.

### 고치는 것 (기준)

1. **감사의견 사건일 = 그 사업연도 사업보고서의 최초 접수일**(감사보고서가 공개되는 시점, 패널의 T 와 같은 출처).
   자기 연도 의견은 `사건일 > T` 조건으로 자동 제외되고, `과거사건`(첫 사건일 ≤ T)에는 포함된다.
   최초 접수일을 알 수 없는 경우는 기존 날짜를 쓰고 건수를 기록한다.
2. **회생절차**: 같은 기업의 직전 회생 공시 후 365일 이내의 공시(첨부정정·개시결정·폐지결정 등)는 **같은 절차의 후속 공시**로 보고 사건에서 뺀다.
   사건일은 절차의 첫 공시일이다.
3. **정정본 재무값** (API 가 최신 정정본만 준다 — 원본 값을 받을 수 없다): 행마다 재무 데이터의 실제 접수일을 저장하고
   `정정본재무` 표시를 단다. 주 결과는 지금처럼 전체로 보고하고, **정정본 행을 뺀 결과를 민감도로 병기**한다(검증·평가). 학습 표본은 바꾸지 않는다.
4. **단위 수정은 T 시점 정보로만**: 이번 보고서의 전기 금액으로만 확인한다(다음 해 공시를 쓰지 않는다). 확인되지 않는 10³·10⁶ 점프는 로그자산·증가율 결측.
5. **변화량(Δ)·증가율은 직전 연도가 연속일 때만** 계산한다(연도 공백이면 결측). 2년연속영업손실도 직전 연도가 없으면 결측.
6. **평가 지표**: 재현율@정밀도는 동점을 고려해 고유 점수 경계에서만 계산. 부트스트랩 신뢰구간은 **기업 단위 군집 재표집**(같은 기업의 여러 연도를 함께 뽑음).
7. **엠바고는 창 길이를 따른다**(민감도 데이터셋 365·450일에도 각자의 창으로).
8. 충실도 검사의 문장 판정은 **원본 값**으로(실제 카드와 같은 값).

### 바꾸지 않는 것

- 주 분석 정의(관측 기간 내 첫 부실), 분할, 모델 설정(`early_stopping=True` 포함), 특성 집합, 하이퍼파라미터, 임계값 정의.
- 평가 구간을 **1회** 다시 연다(6번째) — "라벨 오류 수정 후 재평가". 결과를 보고 설정을 바꾸지 않는다.
- 보고: 10-11 결과와 수정 결과를 나란히, 변경 이유와 함께.
