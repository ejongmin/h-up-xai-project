목표는 '다시 돌려서 좋은 수치'가 아니라 **오류가 생긴 경로를 찾아, 재발하면 감지되는 절차**다.
오류가 없다고 보장할 수는 없지만, 발견하고 추적할 수 있는 구조로 만든다.

## 1. 연구 질문 (확정 2026-10-31)

- **주 목적**: 관측 기간 내 첫 부실 예측 — T 시점까지 관측된 부실 이력이 없는 기업이 T 이후 400일 안에 처음 부실해지는가.
- 보조: 전체(반복 포함), 반복 부실. 반복 부실은 과거 이력만으로도 상당 부분 맞혀지므로(1차 검증 PR-AUC 0.214) 주 목적에서 뺀다.
  기존 부실을 다시 찾는 성능과 조기경보 성능을 구분하기 위해서다.
- 관측 한계: 사건 원천이 2015-01 부터라 그 이전 이력은 모른다.

## 3. 데이터 재구축 — 최초 공시 원문

- 원천: DART `fnlttXbrl` — **최초 접수번호(rcept_no)의 원본 XBRL** (`src/hup/xbrl.py`). 최초 접수번호는 공시 목록에서 기업·사업연도별 가장 이른 사업보고서 (`dart.first_filings`).
- 값: 당기 = 종료연도가 사업연도인 맥락, 전기 = 그 전년. 기간 값은 1년(350~380일)짜리만. 연결/별도 축 외의 차원(자본 구성요소 등)이 붙은 값은 버린다.
- 기준: 연결 → 별도 → 축 없음 순 (1차와 같은 원칙). 어느 기준인지 `재무제표기준`에 남긴다.
- **원본이 없는 행**(status 013/014)은 주 분석에서 뺀다. 다른 값으로 대체하면 시점 문제를 다시 만든다. 제외 집단의 특성(연도·사건 수)은 보고한다 (§3-2).
- 계정명 폴백: XBRL 라벨 파일(`lab_*-ko.xml`)의 한글 표준 라벨을 API 의 `account_nm` 처럼 쓴다. 이름은 `features.ACCOUNTS` 의 목록과 **정확히 같을 때만** 맞는다 (§3-4 검산).
- 1차 단위 보정(`fix_units`)은 그대로 적용하되, 아래 검사 관문이 별도로 의심 행을 표시한다.

**시험 수집 (2026-10-31, 사업연도별 4건 × 11년 = 44건)**
- 44건 모두 원본 XBRL 있음. 최초 접수일이 1차 데이터셋의 T 와 23,084행 전부 일치.
- 1차 API 값과 계정별 일치: 정정본이 아닌 행은 대부분 완전 일치. 불일치는 1차에서 `정정본재무=1`인 행에 몰렸다
  (예: 한 FY2021 행은 12개 계정 중 1개만 일치) — 바로 1차에서 T 이후 정보가 섞였던 행이다.
- 전체 수집: `scripts/collect_xbrl.py` (키 2개로 나눠, 캐시 `data/cache/xbrl/`).

### 3-1. 기준시점이 어긋난 3건의 판정 (2026-10-31)

검사 관문 첫 실행에서 '재무 공개일 > T' 3건이 나왔다 — 공시 목록의 최초 접수일보다 그 접수번호의 날짜가 늦다.
같은 사유로 묶지 않고 공시 이력과 원문 표지를 확인했다.

| 사례 | 목록 접수일 | 접수번호 | 확인 | 처리 |
|---|---|---|---|---|
| A사 FY2024 | 2025-03-31 | 2025-04-01 00:00대 (끝자리 000004) | 그 사업연도 사업보고서는 이 한 건(이후 06-04 기재정정). 같은 최초 공시가 자정을 넘겨 번호를 받음 | **최초 공개 자료로 확인** → T 그대로 |
| B사 FY2023 | 2024-03-19 | 2025-08-28 | 표지는 '2024년 3월 19일 제출'이나 파일은 2025-08 에 다시 등록된 번호 | **확인 불가** → 주 분석 제외 |
| B사 FY2024 | 2025-03-11 | 2025-08-28 | 같음 | **확인 불가** → 주 분석 제외 |

규칙: 원문으로 최초 공개 자료임을 확인한 사례만 T 를 유지한다(`config.FIRST_FILING_CONFIRMED` — 현재 A사 1건). **하루 차이를 자동으로 허용하지 않는다.**
새로 발견되는 불일치는 원문 확인 전까지 최초 공개 시점의 값인지 확인할 수 없는 것으로 보고 주 분석에서 빼고 `results/v2/data_check/시점확인불가.csv` 에 남긴다. T 를 재등록 날짜로 늦추면 '최초 공시 시점의 예측'과 다른 문제가 되고 라벨·과거 이력·분할이 함께 바뀐다
(처음에는 '둘 중 늦은 날'로 T 를 옮겼다가 이 이유로 되돌렸다).

## 5. 모델 — 기준 모델부터, 같은 조건에서 비교

### 5-1. 1차의 주 모델 선택 근거 (기록, 2026-10-31)

1차에서 히스토그램 기반 그래디언트 부스팅(HistGradientBoosting)을 주 모델로 쓴 이유:
1. **재무변수 사이의 복합적 관계** — 같은 적자라도 부채 부담과 현금흐름에 따라 위험이 달라질 수 있다. 의사결정나무 기반 모델은
   조건의 조합과 비선형 관계를 표현할 수 있고, 기본 로지스틱 회귀는 변수를 따로 구성하지 않으면 이를 표현하기 어렵다.
2. **구현과 실험 관리** — 코드에 적힌 근거는 결측을 직접 처리하고 scikit-learn 만으로 추가 라이브러리 없이 쓸 수 있다는 것(`src/hup/model.py`의 `ensemble`).
   다만 파이프라인에 별도 결측 처리가 있으므로, 결측 처리 능력이 성능을 높였다고 주장할 수는 없다.
3. **예측과 설명 검증을 함께** — 주 모델의 예측을 SHAP 으로 분석하고 로지스틱 계수 방향과 비교하는 구조를 만들었다.
   SHAP 은 다른 모델에도 적용되므로 이것이 이 모델의 우수성 근거는 아니다.

비교가 부족한 점:
- XGBoost · LightGBM · CatBoost · 랜덤포레스트 비교 기록은 없다.
- TabPFN 은 비교 코드가 있으나 라이선스 수락 대기로 실행되지 않았다 (결과 파일이 없다 — 1차에 우리 모델 행만 담긴 빈 결과 파일이 있었으나 10-31 정리).
- isotonic 은 별도 예측 모델이 아니라 출력 확률 보정 단계다.
- 모델 간 성능 차이의 통계적 유의성은 검정하지 않았다.

따라서 "성능이 가장 좋아서 선택했다"고 말하지 않는다. 정확한 표현:

> 로지스틱 회귀를 해석 가능한 기준 모델로 두고, 재무변수의 비선형 관계와 상호작용을 학습하기 위해 히스토그램 기반 그래디언트 부스팅을
> 주 모델로 사용했습니다. 구현 환경과 실험 관리의 용이성도 고려했습니다. 다만 여러 알고리즘 가운데 최적이라는 점까지 검증한 것은 아닙니다.

### 5-2. 2차 절차

데이터 시점 문제를 먼저 해결한 뒤(§3·§4), **같은 데이터 · 같은 분할 · 같은 튜닝 예산**에서 후보를 비교하고 **검증 구간 결과로** 고른다.
모델 수를 늘리는 것보다 비교 조건을 공정하게 만드는 것이 우선이다.

**공통 조건** (모든 후보 동일)
- 변수: `features.FEATURE_COLS` 28개(재무비율·특수 항목 19 + 변화량 6 + 증가율 2 + 2년연속영업손실) + 학습 구간에서 정한 결측 더미. 시장변수·공시행태 변수 제외.
- 전처리: 학습 구간 기준 1·99% 윈저라이즈(이진 변수 제외), 학습 구간 중앙값 대치 (`dataset.fit_clean`).
- 분할: 학습 T 2016~2021(검증 단계는 라벨 창이 2022-01-01 전에 끝나는 행만 — 엠바고), 검증 T 2022~2023, 평가 T 2024~2025. 검토 대상 행·§3-1 제외 행은 뺀다.
- 학습 대상: 전체 행(첫 부실·반복 모두)으로 학습하고, 선택과 평가는 첫 부실 집단에서 한다. 클래스 가중 'balanced'.
- 확률 표시용 isotonic 보정은 선택이 끝난 뒤 최종 모델에만 붙인다 (순위 비교에는 비보정 점수).

**후보와 튜닝 설정 — 모델당 20개, 코드에 고정** (`model.GRIDS`, `model.candidate`)

| 모델 | 고정 | 탐색 (20개) |
|---|---|---|
| 로지스틱 회귀 (기준) | 중앙값 대치 · 표준화 · liblinear | C ∈ {0.001, 0.003, 0.01, 0.03, 0.1, 0.3, 1, 3, 10, 30} × 규제 {L2, L1} |
| HistGradientBoosting | max_iter 400 · 조기 종료 켬 · 시드 42 | 학습률 {0.03, 0.05, 0.1} × 잎 수 {7, 15, 31} × 잎 최소 표본 {20, 50, 100} × L2 {0, 1} 54개 중 시드 0 으로 뽑은 20개 (목록은 `model.GRIDS["HistGB"]`) |
| 랜덤포레스트 | 나무 500 · max_features √p · balanced_subsample · 시드 42 | 최대 깊이 {없음, 6, 10, 16} × 잎 최소 표본 {1, 5, 20, 50, 100} |

추가 의존성 없이(scikit-learn) 돌릴 수 있는 세 가지로 한다 — 단순한 기준 모델과 서로 다른 나무 결합 방식(부스팅·배깅).

**절차**
1. 로지스틱부터 20개 설정을 검증 구간에서 평가하고, 고른 설정의 계수 부호를 재무 상식과 대조한다.
2. HistGB · 랜덤포레스트도 같은 방식으로 각자 20개 중 최고 설정을 고른다 (검증 첫 부실 PR-AUC).
3. **모델 간 선택**: 검증 첫 부실 PR-AUC 가 가장 높은 모델과 로지스틱의 차이를 쌍 부트스트랩(기업 군집, 1,000회) 95% 구간으로 본다.
   구간이 0 을 포함하면 운영 규칙상 로지스틱을 택한다. **이는 두 모델의 성능이 같다는 뜻이 아니라, 차이를 확인할 만큼 증거가 충분하지 않다는 뜻이다.**
   각 모델이 20개 중 최고를 골랐으므로 검증 구간 점수는 낙관적이다 — 이 점수는 선택에만 쓰고 성능으로 보고하지 않는다.
4. 평가 구간은 모델 선택에 쓰지 않는다. 선택이 끝난 뒤 최종 모델 하나로 '수정 후 재평가'를 한 번 한다 (§6).
5. 설명 카드 · 사이트는 데이터와 평가 기준이 안정된 뒤 2차 모델에 연결한다.

### 5-3. 실행 규칙 (2026-10-31, 첫 실행 전에 추가)

- **최종 모델 = 검증 단계에서 고른 그 모델 그대로** (엠바고 학습 표본으로 학습한 것). 학습 구간 전체로 다시 학습하지 않는다.
  다시 학습하면 점수 척도가 바뀌어 검증 구간에서 정한 경보 임계값(§6)을 '그대로' 적용할 수 없다. 엠바고 학습 표본의 라벨 창은 2022-01-01 전에 끝나므로 평가 구간과도 겹치지 않는다.
- 같은 PR-AUC 면 목록 앞의 설정(`model.GRIDS` 순서)을 고른다. 시드: 모델 42, 부트스트랩 0.
- 표시용 확률은 고른 설정을 같은 학습 표본에서 isotonic 5겹 교차 보정한 별도 모델에서 낸다 (Brier 는 이것으로). 순위·임계값은 비보정 점수.
- **실패도 기록**: 설정이 학습·예측에 실패하면 오류를 그대로 결과표에 남기고 그 설정은 후보에서 빠진다. 다른 설정으로 바꾸지 않는다.
- 실행 기록: 커밋(작업 트리가 깨끗해야 실행), 데이터 해시, 설정 목록, 시드, Python·scikit-learn·numpy·pandas 판, 운영체제를 결과 파일에 함께 저장한다.
- 순서: `scripts/v2_experiment.py select` → 선택 결과 커밋 → `scripts/v2_experiment.py evaluate`(선택 결과가 커밋돼 있지 않으면 실행을 거부, 평가 결과가 이미 있으면 다시 실행하지 않는다).

## 6-2. 정정 평가 — 결과가 확정되지 않은 행 (원칙은 계산 전에 적는다, 2026-11-01)

'평가는 한 번만'은 결과를 보고 유리하게 바꾸지 않기 위한 원칙이지, 평가 자료의 오류를 그대로 두는 규칙이 아니다.

**확인 (성능을 다시 보기 전)** — 예측 기간이 사건 목록 수집일(2026-09-04) 뒤에 끝나는 평가 행 2건을 2026-11-01 공시 목록으로 개별 확인했다.

| 행 | T | 예측 기간 끝 | 그 사이 공시 | 판정 |
|---|---|---|---|---|
| 1 (부실 이력 있음) | 2025-09-18 | 2026-10-23 | 다음 사업보고서 2026-09-10 감사의견 적정, 회생 공시 없음 | **사건 없음 확정** — 라벨 맞음 |
| 2 (첫 부실 대상) | 2025-12-22 | 2027-01-26 | 2026-03-20 보고서 적정, 회생 공시 없음 (2026-11-01 까지) | **결과 미확정** — '사건 없음'으로 처리돼 있었다 |

두 기업 모두 결산월을 바꾼 기업이라 라벨 누락 가능성도 함께 점검했다(`scripts/audit_label_gaps.py`): 전체 2차 데이터에서 예측 창 안에 접수된 최초 사업보고서의
비적정 감사의견 471건이 모두 y=1 이었고 누락은 0. 접수번호로 의견을 특정하지 못한 28건은 그 사업연도 응답에 비적정 의견이 없었다.

**원칙** — 평가 판정일 현재 예측 기간이 끝나지 않았고 사건도 없는 행은 결과 미확정으로 보고 주 지표 계산에서 뺀다. 예측 기간이 끝났거나 사건이 이미 있는 행은 넣는다.
**모델 · 변수 · 경보 임계값 · 평가 지표는 바꾸지 않는다** — 동결본(`results/v2/freeze/모델.joblib`)으로 같은 계산을 하되 대상 행만 원칙대로 고친다.
모델 재선택이나 튜닝이 아니다. 기존 결과(`평가결과.json`)는 그대로 두고 정정 결과를 따로 저장해 둘 다 보고한다 (`scripts/v2_corrected_eval.py`).

**결과** (`results/v2/final/정정평가결과.json`) — **결과가 아직 확정되지 않은 1행**(첫 부실 대상)을 제외했다.

| 첫 부실 (주 분석) | n | 사건 | PR-AUC (95% 구간) | 경보 (동결 임계값) |
|---|---|---|---|---|
| 기존 평가 (10-31) | 4,456 | 51 | 0.0762 (0.0501 ~ 0.1292) | 1건 · 적중 0 |
| 동결 모델로 재계산 (정정 전) | 4,456 | 51 | 0.0762 (0.0501 ~ 0.1292) | 1건 · 적중 0 |
| **정정 후** | **4,455** | **51** | **0.0762 (0.0501 ~ 0.1292)** | 1건 · 적중 0 |

PR-AUC 는 **소수 넷째 자리 기준 동일**하다(전체 4,771행 · 반복 부실도 같음). 결론은 바뀌지 않는다.

## 7. 기업 위험 검토 도구 (`site/`, 2026-11-01)

https://ejongmin.github.io/h-up-xai-project/ — 2차 동결 모델의 평가 구간(T 2024~2025) 카드. 1차 화면은 `site/v1/` 에 비교용으로 보존.
`scripts/site_data_v2.py` 로 생성한다.

| 화면 | 사용자가 확인하는 것 |
|---|---|
| ① 공시 기준월 · 예측 기간 | 언제 알 수 있었던 정보로 판단했는가 (최초 공시 원본 값) |
| ② 위험 순위 | 같은 집단 안 순위 · 사전 경보 기준 초과 여부. **확률은 표시하지 않는다** (첫 부실 집단 보정 불량, §6-1) |
| ③ 설명 카드 | 어떤 재무 요인이 순위를 올렸나/내렸나, 표본 내 위치, '무엇이 달라지면' 순위 변화(모델 기준) |
| ④ 공시 재무비율 · 원문 링크 | 근거 수치를 직접 확인 — 원문 링크와 기업명은 **로컬 전용** 파일(`site/data/local_names.js`, 커밋 안 함)이 있을 때만 |
| ⑤ 검사 · 데이터 주의 · 더 확인할 곳 | 보류·교정 여부, 대치값·별도재무제표·이후 정정 공시 여부, 사업보고서에서 추가로 볼 항목 |
| ⑥ 이후 실제 사건 (펼치기) | 당시 예측과 나중 결과 — 관측이 끝나지 않은 행은 그렇게 표시 |

- 첫 부실 대상과 부실 이력 있음을 탭으로 나눈다. 시연 세 사례(일반 설명 · 오류 수정 · 설명 보류)를 첫 화면에 둔다.
- 첫 화면에 '할 수 있는 것 / 할 수 없는 것'을 숫자와 함께 적는다 — 순위는 무작위보다 낫지만 경보로는 부족하다.
- 익명: 기업명 · 종목코드 · 고유번호 · 정확한 공시일 없음(공시 월만). 업종은 대분류.
- `?mode=score` — 사용성 점검용: 순위와 원문만 보여준다 (docs/16).
- 활용 가능성(투자 대상 검토 보조, 거래처 점검 참고, 신용심사 지원 자료, 모델 내부 점검, 금융 교육)은 **가능성**이다. 정확도 향상·손실 감소를 입증한 것이 아니며,
  상장사 데이터라 비상장·중소 거래처에 그대로 적용된다고 말하지 않는다.

## 9. 11~13주차 분석을 2차 동결 모델로 다시 (실행 전 고정, 2026-11-01)

1차의 설명 충실도 · 오분류 · 추가 공시정보 분석은 1차 데이터·모델 결과다. 같은 질문을 **동결 모델(`results/v2/freeze/모델.joblib`)과 검증 구간(T 2022~2023)만으로** 다시 낸다.
평가 구간은 쓰지 않는다. 1차 결과는 비교용으로 남긴다. 스크립트 `scripts/v2_analysis.py`, 결과 `results/v2/analysis/`.

| 주차 | 질문 | 방법 (1차와 같은 절차, 모델·데이터만 2차) | 대상 |
|---|---|---|---|
| W11-1 삭제 검사 | 설명이 모델의 실제 근거를 반영하는가 | 위험 점수 상위 300건에서 SHAP 상위 k개(1·2·3·5·8·12)를 학습 구간 중앙값으로 바꿀 때 점수 하락 vs 무작위 k개(시드 0) | 검증 첫 부실 (주), 검증 전체 (보조) |
| W11-2 사실 단정 · 보류 | 카드 문장이 재무 사실과 맞는가, 믿을 수 없는 설명을 거르는가 | 집단 내 위험 상위 10% 카드에서 '구 방식이면 사실과 다른 단정' 줄의 비율(고친 뒤 0 이어야 함), 보류율 · 보류 사유 | 검증 첫 부실 · 부실 이력 있음 |
| W12 오분류 | 놓친 부실과 잘못 짚은 기업은 어떤 모습인가 | 위험 점수 상위 5% 를 고위험으로 보고 미탐 · 정탐 · 오탐 · 정상의 원본 재무 중앙값과 수 | 검증 첫 부실 (주), 검증 전체 (보조) |
| W13 추가 공시정보 | 감사인 텍스트 · 공시 행태 신호가 재무비율 위에 정보를 더하는가 | 신호 4종(계속기업 불확실성 · 강조사항 · 감사인 교체 · 제출기한 연장)의 사건군/정상군 비율, 그리고 동결 설정 그대로 신호를 더해 재학습한 모델과 동결 모델의 검증 첫 부실 PR-AUC 차이(기업 군집 쌍 부트스트랩 1,000회) | 학습 → 검증 |

- W13 신호는 시점 정합을 위해 **전년(FY t−1) 값**을 쓰고, 제출기한 연장만 T 에 공개된 당해 값을 쓴다(1차와 같음). 감사인 텍스트는 감사의견 API 의 최신 판이라 정정 공시 영향이 있을 수 있다 — 한계로 적는다.
- W13 의 차이 구간이 0 을 포함하면 '추가 이득을 확인하지 못했다'고 쓴다(같다는 뜻이 아니다). 포함하지 않아도 동결 모델은 바꾸지 않는다 — 이 결과는 향후 과제다.
- W11-1 의 하락은 '모델이 그 근거를 쓴다'를 보일 뿐 원인을 보이지 않는다.
- 1차의 인위 오류 탐지 실험(규칙 연결 확인)은 규칙이 바뀌지 않아 다시 하지 않는다.
