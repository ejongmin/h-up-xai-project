## 1. 계수 부호 검산 ★ 가장 급함

### 왜 하나요

모델이 "부채비율이 높으면 위험하다"처럼 재무 상식과 같은 방향으로 학습했는지 보는 겁니다.
**부호가 반대면 대개 모델이 똑똑한 게 아니라 데이터가 잘못 만들어진 것**입니다.
여기서 이상이 나오면 뒤에 쌓은 모든 결과가 흔들립니다. 그래서 제일 먼저입니다.

### 지금 상태

변수 17개 중 **13개는 기대와 맞고 4개가 반대**입니다.

| 변수 | 계수 | 기대 부호 | 제 판단 |
|---|---|---|---|
| 영업이익률 | **+0.197** | − (높으면 안전) | ROA와 겹쳐서 ROA가 효과를 흡수 |
| Δ부채비율 | **−0.153** | + (오르면 위험) | 부채비율 수준값과 겹침 |
| 영업현금흐름/부채 | +0.044 | − | 계수가 작아 잡음 수준 |
| 매출증가율 | +0.066 | − | 계수가 작아 잡음 수준 |

제가 "공선성(변수끼리 겹침) 때문"이라고 판단했습니다. 근거는 VIF라는 지표인데,
영업이익률이 11.32로 기준(10)을 넘습니다. 그리고 상관계수를 보면
영업이익률 ↔ 순이익률 0.889, 영업이익률 ↔ 영업현금흐름/매출 0.885로 거의 같은 변수입니다.

### 무엇을 봐주시면 되나요

**이 설명이 재무적으로도 납득되는지**만 봐주세요. 구체적으로 두 가지입니다.

1. 영업이익률과 ROA가 실질적으로 같은 정보를 담는다고 보는 게 맞습니까?
   (ROA = 순이익/자산, 영업이익률 = 영업이익/매출 — 분자·분모가 다른데 왜 겹치는지)
2. Δ부채비율이 음수인 게 정말 공선성 때문일까요, 아니면 다른 재무적 이유가 있을까요?

### 파일

## 3. 관리종목 사유 판정

### 왜 하나요

지금 우리 부실 정의는 **감사의견 비적정 + 회생절차**입니다(주 정의).
여기에 **관리종목 지정**을 더한 보조 정의로도 모델이 비슷하게 작동하는지 보면,
"우리가 정한 정의에 우연히 맞춘 모델"이 아니라는 걸 보일 수 있습니다.
발표에서 강한 방어 논리가 됩니다.

### 문제

관리종목 지정 사유에는 두 종류가 섞여 있습니다.

- **재무 사유** — 자본잠식, 매출액 미달, 영업손실 지속 → **부실이 맞습니다**
- **비재무 사유** — 공시 불이행, 사외이사 요건 미달, 지분분산 미달 → **부실이 아닙니다**

비재무 사유를 부실로 라벨링하면 모델이 재무 신호가 아니라 엉뚱한 걸 학습합니다.
그런데 **공시 제목에는 사유가 안 나옵니다.** 본문을 열어야 알 수 있습니다.

### 무엇을 하나요

제가 후보 목록을 자동으로 뽑아뒀습니다. **`reason_is_financial` 열만 채워주시면 됩니다.**

```
data/manual/kind_events_후보.csv
```

| 열 | 내용 |
|---|---|
| corp_name | 기업명 |
| event_date | 공시 접수일 |
| event_type | 관리종목 / 상장폐지 |
| detail | 공시 제목 |
| rcept_no | **접수번호 — 아래 주소로 원문을 봅니다** |
| **reason_is_financial** | **← 여기에 Y 또는 N** |

원문 보는 법: 아래 주소의 `접수번호` 자리에 `rcept_no` 값을 넣으면 됩니다.

```
https://dart.fss.or.kr/dsaf001/main.do?rcpNo=접수번호
```

**Y로 표시할 것**: 자본잠식, 자기자본 미달, 매출액 미달, 영업손실 지속, 감사의견 관련
**N으로 표시할 것**: 공시 불이행, 사외이사·감사위원회 요건 미달, 지분분산 미달,
주식 분산 기준 미달, 회생절차 관련(이미 주 정의에 있음)
**판단이 안 서면**: 비워두고 알려주세요. 애매한 건 제외하는 게 낫습니다.

### 채운 뒤

파일 이름을 `kind_events.csv`로 바꿔서 저장하면 코드가 자동으로 읽습니다.

```bash
python -m hup.cli build        # 보조 정의를 포함해 데이터셋 재생성
```

## 4. 설명 카드 문안 검토

### 왜 하나요

이 프로젝트의 최종 산출물은 성능 숫자가 아니라 **사람이 읽는 설명 카드**입니다.
"이자보상배율 SHAP +0.34"는 설명이 아니고, 재무 담당자가 읽는 문장이어야 합니다.

문안은 제가 썼는데, 저는 재무 문서를 실제로 써본 적이 없습니다.

### 지금 카드

```
모형 추정 부실확률 27.3%
위험을 높인 요인
  - 자본잠식 정도가 큽니다 (실측 0.52)
  - 자산을 굴려 벌어들이는 이익이 적습니다 (실측 -0.15)
  - 순손실 구간입니다 (실측 -3.52)
  - 1년 내 갚을 돈에 비해 현금화 가능한 자산이 부족합니다 (실측 0.66배)
위험을 낮춘 요인
  - 규모가 큰 편입니다 (실측 26.69)
  - 자기자본이 두텁습니다 (실측 0.71)
```

### 봐주실 것

1. **이 문장들이 심사 의견서나 내부 보고에 그대로 들어갈 수준입니까?**
   어색한 표현, 실무에서 안 쓰는 말이 있으면 고쳐 주세요.
2. **"규모가 작은 편입니다"를 위험 요인으로 쓰는 게 맞습니까?**
   데이터상 규모가 작을수록 사건이 14배 잦습니다(5.66% vs 0.41%).
   틀린 말은 아닌데, 실무 문서에서 이게 근거로 통하는지 모르겠습니다.
3. **확률을 27.3%처럼 소수점까지 보여주는 게 나은지**, 등급이나 구간이 나은지.

문안은 여기 있습니다:

```
src/hup/explain.py   →  PHRASE 사전 (변수마다 위험/안전 문장 한 쌍)
```

고칠 문장을 알려주시면 제가 반영하겠습니다. 직접 고치셔도 됩니다 —
`("위험 쪽 서술", "안전 쪽 서술", "단위")` 형식이고, **순서가 중요합니다**(위험이 먼저).

```bash
python -m hup.cli shap         # 카드 예시 3건 출력
```
