# 평가 지표 체계 (7주차 확정, 2026-09-08)

> 사건 비율이 2.3%인 데이터에서 무엇을 보고하고 무엇을 보고하지 않을지 못박는다.
> 이 문서를 먼저 쓴 이유는, 결과를 본 뒤에 지표를 고르면 원하는 결론이 나오기 때문이다.

## 1. 보고하는 지표

| 지표 | 쓰는 이유 | 함께 적어야 하는 것 |
|---|---|---|
| **PR-AUC** | 주 지표. 불균형에서 순위 성능을 정직하게 반영 | **기준선 = 사건 비율.** 없으면 해석 불가 |
| ROC-AUC | 보조. 문헌 비교용 | 단독 인용 금지 — 불균형에서 낙관적으로 보인다 |
| **재현율@정밀도 0.3 / 0.5** | 실무 언어. "오탐을 얼마나 감수하면 몇 건 잡나" | 임계값 기반이라 표본이 적으면 매우 불안정 |
| **Brier** | 확률 보정 상태. 설명 카드에 확률을 쓰므로 필수 | 보정 전후를 함께 |
| **부트스트랩 95% CI** | 사건 수가 적어 점추정만으로는 아무 말도 못 한다 | 모든 성능 수치에 예외 없이 |

### PR-AUC 는 기준선과 함께 쓴다

PR-AUC 0.15 는 그 자체로 아무 의미가 없다.
사건 비율이 0.02 면 기준선 대비 7.5배지만, 0.14 면 사실상 아무것도 못 한 것이다.
**기준선 없는 PR-AUC 는 해석할 수 없는 숫자다.** 표에 항상 "기준선 대비 N배"를 병기한다.

## 2. 보고하지 않는 지표

| 지표 | 이유 |
|---|---|
| **정확도(Accuracy)** | 전부 정상으로 찍어도 97.7%다. 코드로 차단했다 (`test_metrics_are_not_accuracy`) |
| F1 | 정밀도·재현율의 임의 가중. 실무에서 둘의 비용이 다른데 1:1 로 섞는다 |
| 단일 임계값 기준 지표 일반 | 임계값을 어디 두느냐가 결과를 지배한다. 굳이 쓰면 임계값 선정 근거를 함께 |

## 3. 유의성 보고 규칙

**(a) 계수 유의성은 군집 보정 후로만 쓴다.**
기업-연도 패널이라 같은 기업의 여러 연도가 독립이 아니다(Shumway 2001).
학습 구간 기업당 평균 5.91년 → 검정통계량을 √5.91 = 2.43 으로 나눈다.
보정 전 유의 18개 → 보정 후 11개. **보정 전 숫자는 보고서에 쓰지 않는다.**

**(b) 신뢰구간이 겹치면 "낫다"고 쓰지 않는다.**
8주차 설계 비교에서 매칭 학습·가중치·언더샘플링·격년 학습이 전부 겹쳤다.
겹치는데 점추정만 보고 우열을 말하면 그건 결과가 아니라 잡음이다.

**(c) 공선성이 있는 변수의 계수 부호는 인용하지 않는다.**
영업이익률 VIF 11.32. 축소 변수셋 결과를 쓰거나, SHAP 방향을 쓴다.

## 4. 평가 구간 사용 규칙

```
학습 2016~2021 공시분   →  모델 적합
검증 2022~2023 공시분   →  모든 튜닝·설계 비교·진단
평가 2024~2025 공시분   →  최종 모델 확정 후 단 1회
```

- 진단·절제·비교는 **예외 없이 검증 구간에서** 한다
- 평가 구간을 연 시점과 이유를 기록한다 (`docs/10_실측결과.md` §3-3)
- 평가 결과가 나쁘게 나와도 **돌아가 튜닝하지 않는다.** 그러면 평가 구간이 아니게 된다

> 개발 중 이 규칙을 어기고 평가 구간을 3회 열었다. 기록을 남기고 최종보고서에 싣는다.
> 감추면 위반이고, 밝히면 한계 기술이다.

## 5. 검증 구간을 넓힌 근거 (2026-09-08)

| | 검증 2023 단독 | 검증 2022~2023 |
|---|---|---|
| 검증 사건 | 60건 | **112건** |
| PR-AUC | 0.3468 | 0.3864 |
| 95% CI 폭 | 0.2406 | **0.1958** (19% 축소) |
| 학습 사건 | 293건 | 241건 |

사건 60건으로는 8주차의 어떤 설계 비교도 신뢰구간이 겹쳐 판단이 불가능했다.
학습 사건이 줄어드는 대가를 치르고도 검증력을 얻는 쪽이 낫다고 판단했다.
**평가 구간은 건드리지 않았다.**
