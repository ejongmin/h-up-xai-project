# 국내 상장기업 부실예측 모델과 설명의 타당성 검증

한국외국어대학교 진로탐색학점제 **H-UP 12기** · 팀 종민재 (이종민 · 정민재)
지도교수 공형우 (Finance&AI 융합학부) · 2026-09-01 ~ 2026-12-14

> DART 공시 재무제표로 부실 사건을 예측하는 모델을 만들고,
> **그 모델이 내놓은 판단 근거가 믿을 만한지**를 검증하는 15주 프로젝트입니다.
> 목표는 성능이 아니라 모델이 무엇을 보고 무엇을 못 보는지를 규명하는 것입니다.

## 부실 사건 정의

**주 정의** — 감사의견 비적정(의견거절·부적정·한정) 또는 회생절차 개시 신청.
둘 다 재무 상태와 인과적으로 연결되고 발생 시점이 공시로 명확합니다.

**제외** — 금융업(KSIC 64~66), 스팩·리츠, 비12월결산. 관리종목 지정은 재무/비재무 사유가
혼재해 보조 정의로 분리했습니다.

**시점** — 기준시점 T는 결산일이 아니라 **DART 접수일자**입니다.
재무제표는 결산일이 아니라 공시일에 이용 가능해지기 때문입니다.

## 이 저장소에서 찾을 만한 것

방법론적 함정을 실제 데이터에서 확인하고 고친 기록입니다. 몇 가지만.

**12개월 예측 창이 사건의 3분의 1을 지웁니다.**
사업보고서 제출간격 중앙값이 364일이라 12개월 창이 분포 한가운데를 자릅니다.
게다가 잘려나가는 사건은 무작위가 아닙니다 — 제출기한을 연장한 기업(감사가 제때 안 끝난 기업)의
창 초과율이 **79.8% vs 33.2%로 2.4배**입니다. 가장 중요한 사건부터 지워집니다.
→ 주 분석 창을 400일로 올렸습니다. ([`docs/01`](docs/01_부실사건정의_데이터설계.md) 부록 A-2)

**감사의견 라벨은 동어반복이 되기 쉽습니다.**
감사의견은 그 사업연도 사업보고서 *안에* 들어 있습니다. 같은 보고서의 재무제표로
그 의견을 예측하면 성능은 완벽하고 결과는 무의미합니다.
Ohlson(1980)이 이미 다룬 함정이며, `tests/test_smoke.py::test_label_timing`이 이 조건을 지킵니다.

**부실은 급작스럽지 않습니다.**
사건 3년 전 시점에 이미 정상군과 크게 벌어져 있습니다(이자보상배율 t-3 −0.30 vs 정상군 +1.94).
그래서 변화량 변수의 판별력이 수준값의 1/50에 그칩니다 — 변화가 신호가 아니라 수준이 이미 신호입니다.

**모든 설계 비교의 신뢰구간이 겹칩니다.**
매칭 학습, 클래스 가중치, 언더샘플링, 인접 연도 제거를 비교했지만 어느 것도 유의하게 낫지 않습니다.
검증 구간 사건이 60건이라 이 정도 차이를 구분할 검정력이 없습니다. 그것이 결과입니다.

## 재현

```bash
cp .env.example .env          # DART_API_KEY 입력. 키는 코드에 넣지 않는다
uv venv --python 3.12 && uv pip install pandas scikit-learn matplotlib shap pykrx

python tests/test_smoke.py      # 규칙 점검 (키 불필요)
python tests/test_pipeline.py   # 합성 데이터 전 구간 예행 (키 불필요)

python -m hup.cli probe      # 계정 매핑 성공률 표본 측정 — 본수집 전에 먼저
./run_collect.sh 0/2 "$DART_API_KEY"     # 수집. 감시 루프가 죽으면 되살린다
python -m hup.cli build      # 패널 + 라벨 + 창 민감도
python -m hup.cli eda        # 탐색적 분석
python -m hup.cli train      # 시점 분할 → 로지스틱/앙상블
python -m hup.cli diagnose   # VIF · 축소셋 부호 · Shumway 군집 표준오차
python -m hup.cli calibrate  # 확률 보정 비교
```

수집은 일 20,000건 한도에 걸리면 정상 종료합니다. 캐시가 남으므로 다음 날 같은 명령으로 이어집니다.
`data/cache/`는 며칠치 할당량 그 자체입니다 — 백업 없이 지우지 마세요.

## 이 프로젝트에서 하지 않는 것

1. **정확도 보고** — 사건 비율이 2.3%면 전부 정상으로 찍어도 97.7%입니다
2. **무작위 분할** — 시점 분할만. 미래 정보가 과거 예측에 들어가면 끝입니다
3. **전체 데이터로 산출한 정제 기준** — 윈저라이즈·대치값은 학습 구간에서만
4. **평가 구간 재사용** — 최종 모델 확정 후 1회. 개발 중 3회 열었고, 그 기록을 [`docs/10`](docs/10_실측결과.md) §3-3에 남겼습니다
5. **성능이 안 나온다고 데이터 손보기** — 낮은 성능은 결과지 실패가 아닙니다

## 데이터와 공개 원칙

- 사용 데이터는 **DART 전자공시시스템 등 공개 공시자료**뿐입니다
- 본 프로젝트는 **특정 기업에 대한 투자 판단이나 신용등급을 제공하지 않습니다**
- 결과물에 실명 기업의 개별 위험도 수치를 공개하지 않고, 분석 방법론과 익명화된 사례만 제시합니다
- 수집한 원본 데이터는 저장소에 포함하지 않습니다 (`data/`는 버전관리에서 제외)
- 국내 상장기업의 부실 사건은 표본이 적어 모델 성능에 구조적 한계가 있으며,
  이를 감추지 않고 **한계 자체를 분석 결과의 일부로** 기술합니다
